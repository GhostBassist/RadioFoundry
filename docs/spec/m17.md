# M17 packet framing

The [M17 air interface, Part I](https://spec.m17project.org/files/M17_spec.pdf) specifies 4FSK at
4,800 symbols/s with outer deviation of 2,400 Hz and root-raised-cosine shaping with roll-off 0.5.

The shared frame codec in `core/m17/` implements sections 2.4–2.7 and 2.9.1 at the aligned frame boundary.
It uses the shared constraint-length-five convolutional code. Link setup frames use P1 puncturing and CRC-16/M17.
Packet frames use P3 puncturing and carry 25 payload bytes plus a chunk index or final byte count. Both use
the appendix F interleaver and appendix B randomizer. Packed frames include the sync word and hold 192 symbols
(48 bytes), with the most significant dibit first.

The packet engine builds link data from a source callsign, destination callsign or broadcast, and Channel
Access Number (CAN). Callsigns use the six-byte base-40 representation in appendix A. An empty or invalid
source is refused. The receiver can accept all CAN values or require the channel's configured CAN.

The packet layer splits an application payload and its CRC into sequential chunks. The receive path rejects
sequence errors and exposes the application payload only after validating its CRC. The transmitter emits the
packet preamble, link setup, packet frames, and end-of-transmission marker as consecutive 40 ms blocks.
The shared air framer acquires packet bursts from the tail of the preamble and link sync, then searches for
packet sync at frame boundaries. A symbol gap aborts reassembly. The packet engine connects the framer and
burst writer to an air session. The owner handles tuning, channel access, and RF keying. Receive can run with
a provider that reports approximate transmit shaping or deviation. The packet engine declines to prepare a
transmission on such a provider pending waveform and interoperability measurements.

Host tests exercise reception across provider chunk boundaries and with a damaged sync, and verify that
transmit resumes when the provider queue has room and marks the last chunk. Radio mode selection and the
firmware task that owns the session are pending.

## Voice stream framing

A clear M17 voice stream uses two eight-byte Codec 2 3200 blocks in each 40 ms stream frame. The frame
codec implements P2 puncturing for the frame number and speech payload, and extended Golay coding for
the LICH. The transmit state emits the voice link setup frame, cycles through the six CRC-protected
link setup fragments, and sets the final-frame bit on the last stream frame. The codec reports invalid
LICH separately from speech because a damaged LICH does not invalidate the separately coded speech.

The optional Codec 2 adapter converts one 40 ms block of signed 8 kHz mono PCM in each direction.
It creates fresh encoder or decoder state at the start of a call and preserves that state between
20 ms Codec 2 blocks. The adapter links against a separately supplied
[Codec 2 library](https://github.com/drowe67/codec2). The upstream library retains its LGPL-2.1 license.
The host smoke test runs with `make -C tests/host run-m17-codec2` when the library and development
headers are installed. Supply `CODEC2_CFLAGS` and `CODEC2_LIBS` for a nonstandard installation.

Receive call handling, target-specific Codec 2 linking, and radio audio integration are pending.
